# OVERBOOST + eDrive for iDrive 7 (MGU)

One app with a main menu: **M Vitals**, **eDrive** (plug-in hybrid), **Drag Timer**, **Fault Scanner**, **Engine Config**.
eDrive is the second page of the header, right after M Vitals.
The logic comes from the open-source idrive7-apps project (MIT, `overboost-src/idrive7-apps`, which builds the iDrive 7 screens).

This repository is a **Store source** (mgu-store, "Repo tree" layout, see `docs/PUBLISHING.md` there): the car's Store installs
OVERBOOST from it and updates it when a new version is pushed here. The plain OVERBOOST without eDrive is `mrsradulescu/overboost-app-id7`, the iDrive 8 version is
`mrsradulescu/overboost-app-id8`.
**Add only one of the iDrive 7 sources**: both install the same app (id `overboost`), so the second one would just replace the first.

## Install on the car (once)
1. The head unit needs the Store (mgu-store's installer, or the toolkit) and an internet connection.
2. Store -> **Sources** -> **Add source** -> GitHub -> `mrsradulescu/overboost-edrive-id7` -> channel **Branch: main**.
3. Open the new source, pick **OVERBOOST**, **Install**. The Store installs `app-privacy` and `mgu-render` first when they are
   missing, then builds the app on the unit against the oap-sdk of a stock BMW app (no BMW SDK file is in this repository).
   Restart the head unit if the tile does not show after a few minutes.

An OVERBOOST put on the car by the toolkit is the same app (same id `overboost`). It has no recorded origin, so the Store updates it
from the source whose listing has the same title (`OVERBOOST`): this one.

## Update
Push a new version here, the car's Store shows it under **Updates**. To publish one:
1. Change the code in `overboost-src/overboost/src` / `app`, raise `version` in `overboost-src/overboost/app/version.json`.
2. `python3 tools/store_tree.py` rewrites `apps/overboost/` (the source package the Store builds); `python3 tools/store_tree.py --check`
   says whether it is up to date. Needs Python 3.
3. Commit everything, including `apps/overboost/`, and push to `main`.

On a branch the Store compares **versions**: always raise the version.

## Layout
| Path | |
|---|---|
| `mgu-repo.json` | what the Store reads: one component, `overboost`, an app for iDrive 7 built on the unit |

## eDrive (plug-in hybrid)
The eDrive page is [idrive7-apps](https://github.com/cauliflowermossgrape/idrive7-apps)' eDrive 2.9.2 (MIT, `overboost-src/overboost/src/apps/edrive/`,
licence in `overboost-src/overboost/src/kit/LICENSE.idrive7-apps`), fitted into OVERBOOST. Pages: **Range** (real electric range, live battery
usage, charge, last charge, this drive), **Energy** (where the power goes), **Battery** (health, cells, temperature), **Charge log**; with
*Settings -> Diagnostics pages* also the UDS replies, the battery unit and the scan.

Left out on purpose, as they are not plug-in hybrid things: the 48 V mild-hybrid pages, the 12 V battery pages (only the 12 V voltage stays,
on the Range page), the home-screen widget and the files written for other apps. On a car that is not a plug-in hybrid the Range page says so
(the battery unit does not answer; *Settings -> Plug-in hybrid battery -> Yes* asks it again).

Changes against the stand-alone app: the requires point at OVERBOOST's kit (`../../kit/`), `volt12.js` replaces `battery12.js`, the signals it
watches are in `overboost-src/overboost/app/watch.json`. `node overboost-src/overboost/tools/test_edrive.js` and `test_edrive_live.js` run it
without a car (demo data, and a scripted diagnostic link).

## Fault Scanner texts
`overboost-src/overboost/src/dtc_db.pack` (~3.5 MB) is the fault-text database the Fault Scanner reads; it goes into the package
(`apps/overboost/package/javascript/`). Without it the Fault Scanner lists faults with their codes but shows texts only for the codes
in `known_texts.js`.
